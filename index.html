Privacy policy

What Stepwright keeps, where it keeps it and how to remove it. The short version: nothing you type leaves your browser.

Last updated 10 October 2026

What we collect

Nothing is sent to us. Stepwright has no accounts, no sign-up, no analytics, no advertising and no tracking pixels. It sets no cookies.

What stays in your browser

So the site works the way you left it, a few items are saved in this browser's local storage, on this device only:

  • Display settings: theme and text size.
  • Workflow answers, including the text of any files you attach.
  • A note that you have seen the welcome notice, and your cookie settings.

You choose what is kept in cookie settings. Essential items are always kept, because they are needed to remember your choices.

Files you attach

Attached files are read inside your browser. Text files are added to the workflow file you download; images and PDFs are only listed by name. No file is uploaded.

Hosting

The site is hosted on Render. Like any web host, Render keeps standard server logs, such as IP address, browser type and time of request, to run and secure the service. Stepwright does not receive or use these logs. See Render's own privacy policy for details.

AI tools you paste into

When you copy a prompt or export a workflow and paste it into Claude, ChatGPT, Cursor or another tool, that tool's own privacy policy applies to what you send.

Delete your data

  • On the Settings page, choose Clear workflow answers.
  • In cookie settings, turn off what you no longer want kept. The saved copy is deleted straight away.
  • Or clear this site's data in your browser settings.

Design system

The tokens, type, spacing and component states behind this site, documented for handover to Figma and code. Layer names match the kebab-case class names in the source.

Decision log

Logo lockups

The Stepwright mark is an S that climbs one stair in the middle: each prompt is a step. It is built on a 32px grid with right angles only and reads the same turned 180°. Keep clear space equal to the tile corner radius (9px at 40px) on every side, never go below 16px, and never place the light lockup on a dark ground.

Color

Primitives are raw values and are never used in components. Components read semantic tokens only, which is how the dark and high-contrast themes swap without touching markup.

  • {{ c.name }}{{ c.hex }}
    •
TokenRoleLightDarkHigh contrast
{{ t.token }}{{ t.role }}{{ t.light }}{{ t.dark }}{{ t.contrast }}

Checked pairs (light theme): text on bg 15.3:1, muted text on bg 6.7:1, primary on bg 6.6:1, on-primary text on primary 7.1:1, accent on bg 5.6:1, every status badge 5.5:1 or higher, border-strong on bg 3.3:1 for control edges. Dark theme: every pair 5.7:1 or higher. High contrast: 11:1 or higher.

Typography

Base 16px with line heights on a 4px baseline. Sizes are in rem, so the three visitor text sizes (100%, 112.5%, 125%) scale every style together. Three weights only: 400, 500, 600.

An 8px grid. The 4px half step is only for icon-to-label gaps. Spacing stays in px so it does not grow with the text size setting; text reflows instead.

Elevation and radius

--shadow-1Resting cards in a list. Just enough to lift them off the page.
--shadow-2Code windows, the one focal object per screen.
--shadow-3Popovers, dialogs and toasts that sit above everything.

Radius: 4px badges and line highlights, 8px controls, 12px cards and windows, 16px feature panels. The high-contrast theme removes shadows and uses 2px borders instead.
